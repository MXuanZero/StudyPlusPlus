## 一、项目一句话定位

一个面向“数学和物理基础薄弱学习者”的桌面端控制理论学习网站，以《控制之美》目录为课程大纲，用**交互式可视化 + Python 后端计算 + 全局 AI 对话**帮助用户理解控制理论。

## 四、版本控制规范

- 项目使用 Git 管理，仓库根目录为 `StudyPlusPlus/`。
- **每次完成一个可验证的改动都必须提交 Git**，不允许长期保留未提交修改。
- 提交信息格式：`type(scope): subject`。
- 每个提交只做一件事；提交前运行受影响范围的测试、构建或启动检查。
- 禁止提交密钥、`.env`、`data/*.db`、`.venv/`、`node_modules/`、构建产物。
- 任务完成时必须同步更新 `todo.html`，并将进度更新一并提交。
- 智能体任务汇报必须包含 Git commit hash。

## 五、给智能体团队的通用要求

1. 所有 Python 命令必须使用项目 `.venv`：`.venv/bin/python`、`.venv/bin/pip`。
2. 依赖变更必须同步更新根目录 `requirements.txt`。
3. 不得在代码、前端构建产物或文档中硬编码任何 API Key。
4. 所有接口、组件、数据库表都要有清晰的命名和注释。
5. 每个任务完成后，必须满足 `04_开发任务拆分与验收.md` 中对应验收条件。
6. 涉及数学公式和物理结论的内容，必须与 `03_二阶系统分析模块详细设计.md` 中的定义保持一致。
7. 每完成一个任务或子项，必须同步更新根目录 `todo.html` 中的 `status`、`subtasks[].done` 和 `UPDATE_LOG`。
8. 每次提交 Git 之前，必须验证受影响的代码；每个任务结束时至少有一个对应 Git commit。
